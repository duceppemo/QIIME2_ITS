# Validation run: 2026-09-21 (corrects 2026-09-16)

- **QIIME2**: `rachis-qiime2-2026.7` (q2cli 2026.7.0)
- **ITSxpress**: 2.2.0 (via `qiime itsxpress` plugin)
- **qiime2-its**: 0.3.1 + the fixes released as 0.3.2 (commit `33ed4b3` and later)
- **Result**: all 8 steps (2 classifier trainings + 6 pipeline runs) completed successfully, and
  -- new in this run -- all 22 *output* checks passed (`output_checks.log`; its taxonomy check was then
  relaxed from genus to kingdom + phylum -- see "How to read that" below -- which the same output
  also satisfies).

## Why this run exists: the 2026-09-15/16 classifiers were trained on 4 of 20 sequences

A code review on 2026-09-21 found that `taxonomy.parse_id_table()` returned `{taxid: accession}`.
A dict keyed by taxid holds one accession per taxon, so every reference sequence sharing a taxid
with another one was silently dropped from `taxonomy.txt` -- for both `qiime2-its-train-ncbi` and
`qiime2-its-train-fasta`. On the bundled training set (20 sequences, 4 species; 13 of them
*Eremothecium gossypii*) that left **4 taxonomy lines for 20 sequences**, and QIIME2's
`fit-classifier-naive-bayes` does not object to reference sequences without a taxonomy line: it
quietly trains on the ones that have one. Fixed in commit `c994444` (released in 0.3.1).

**This script passed anyway, twice**, because it only checked exit codes. The 2026-09-16 summary's
statement that taxonomy was "now correct" was true of the *lineage strings* (the rank-mapping fix
it describes is real and stands) but not of the classifiers built from them, which had seen one
sequence per species.

### Measured effect (same reads, same parameters, old vs. retrained classifier)

| scenario | ASVs | lineage changed | classified to species (old -> new) | mean confidence (old -> new) |
|---|---|---|---|---|
| `paired_end` | 13 | 13 | 0 -> 13 | 0.888 -> 0.979 |
| `single_end` | 19 | 19 | 0 -> 19 | 0.911 -> 0.984 |
| `fasta_classifier_classification` | 19 | 19 | 0 -> 19 | 0.911 -> 0.984 |
| `multi_sample_advanced_stats` | 7 | 7 | 0 -> 7 | 0.864 -> 0.964 |

`single_end`, before: 12 ASVs stopped at `k__Fungi;p__Ascomycota`, 6 at `o__Sordariales`, 1 at
`f__Saccharomycetaceae`. After: all 19 are assigned
`...;g__Thermochaetoides;s__Thermochaetoides_thermophila`.

**How to read that.** The numbers show the fix changed what the classifiers learned -- they are
*not* evidence that the new species calls are right. The bundled reads are an environmental
sample unrelated to the 4 training species (`data/SOURCES.md`), so there is no correct species
among the classifier's choices; a naive-Bayes classifier that only knows 4 species will assign the
nearest one, and now that it has seen every reference sequence it does so confidently. That is a
property of a deliberately tiny, closed reference set, not of the pipeline, and it is why this
suite asserts nothing deeper than "every ASV got a real fungal lineage". Whether taxonomy is
biologically sensible is what `--with-unite` (a full UNITE classifier) and the worked example
under `examples/PRJNA767765/` are for. `data/SOURCES.md` was updated accordingly: it used to call
the shallow `k__Fungi;p__Ascomycota` truncation "the expected outcome", which was the under-trained
classifier speaking.

## What changed in the suite itself

`run_validation.sh` now checks output, not just exit codes, so this class of failure stops the run:

- both trainers: exactly one taxonomy line per reference sequence (this check **fails** on the
  2026-09-16 output: 4 lines vs. 20 sequences);
- every pipeline scenario: non-empty `report.pdf` and `run_metadata.json`, and every ASV given a
  real fungal lineage (kingdom + phylum; nothing deeper is asserted, see above);
- `multi_sample_advanced_stats`: alpha and beta group-significance results were written.

It also refuses to wipe a non-empty `output_dir` it did not create, rejects unknown options, reuses
the first `taxdump.tar.gz` download for `train-fasta`, and no longer advertises a
`UNITE_CLUSTER_ID` override that `qiime2-its-train-unite` could never honor.

## Other fixes validated end to end by this run

Up-front input checks (metadata/classifier files exist, every fastq sample has a metadata row,
output folder not inside the input folder, no fastq files in subfolders without `-rc` -- symlinked
fastq files allowed), `-t/--threads` honored by phylogeny and taxonomy classification, QIIME2-style
metadata parsing (`#` comments, `#q2:missing`, BOM, duplicate detection), best-effort
beta-group-significance, and the report fixes (real column names, shared group colors,
"(missing)" group). All six scenarios' reports were generated by this code.

Logs in this directory are from this run; paths were rewritten from the scratch output folder it
used to the default `validation/output/` for readability.
